How one training run moves

1. Dashboard

You review the settings and submit once.

2. Model API

Saves the run as queued in MongoDB.

3. Queue

Redis and Celery hand the job to the worker.

4. Worker

Trains the PyTorch MLP and keeps the best validation epoch.

5. Results

Scores the test split once, saves a checkpoint with its SHA-256.

Never twice

One idempotency key per submission, so a double click starts one run.

No test leakage

Scaling and model choice use training and validation rows only.

Repeatable

Fixed seed, deterministic PyTorch, one CPU thread.

About 1 minute. Follow one run left to right. The dashboard sends a single request; the API stores it as queued; Redis and Celery hand it to a separate worker so the website never freezes; the worker trains the PyTorch network and keeps the epoch with the best validation score; only then is the held-out test split scored, and the checkpoint is saved with a fingerprint we verify before download. Point to the three guarantees underneath: no duplicate runs, no test leakage, repeatable results.
