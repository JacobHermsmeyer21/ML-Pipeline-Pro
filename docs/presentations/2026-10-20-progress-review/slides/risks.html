Bottlenecks and risks

Laptop CPU inference is slow

Reading the first prompt dominates a chat turn; one comparison ran past the 270-second limit.

Plan: done — the agent now runs on Claude through the Anthropic API.

Kubernetes storage fails at startup

The dataset API returns 503: a database connection opens before MongoDB’s replica set is ready.

Plan: replica-set discovery, then rerun the cluster smoke test.

Training can’t run on Vercel

Vercel functions are short-lived and share no disk; training runs minutes and needs its files.

Plan: API and training on Modal with shared storage; Vercel serves the site.

No independent reviewer yet

Concurrency and recovery code has only been reviewed by its own authors.

Plan: ask a peer team to review; disclose the gap until then.

About 1 minute 15 seconds. Four risks, each with its plan. First, the assistant is slow on a laptop CPU because processing the first prompt dominates the turn; we solved it by moving the agent to Claude through the Anthropic API, which answers in seconds. Second, in Kubernetes the database connection opens before MongoDB is ready, so the dataset API returns 503; the fix is replica-set discovery. Third, Vercel's functions are short-lived and have no shared disk, but training runs for minutes and the API and training share dataset and model files. So the API and training both run on Modal with shared storage, and Vercel serves the site; the next slide shows the layout. Fourth, our concurrency code has not had an independent review; we will ask a peer team.
